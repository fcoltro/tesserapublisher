**Tessera Publisher — code and publishing-capability review**

Reviewed 2026-09-10–11, checkout `eb2cd1b`. This is an audit, with no production-code changes.

Tessera has a useful modular foundation, but the current build is not yet a dependable InDesign replacement. The immediate obstacle is correctness across existing features: document safety, text composition, resource ownership, and exported output. Adding more drawing tools before addressing those problems would leave ordinary publishing workflows unreliable.

**Evidence and scope**

- `cargo test --workspace --lib --tests --locked --offline`: **1,562 passed, 0 failed, 7 ignored**. The ignored tests include six GPU tests.
- `cargo fmt --all -- --check`: passed.
- `cargo clippy --workspace --all-targets --locked --offline -- -D warnings`: passed.
- Small independent harnesses reproduced group/clipboard loss, package failures, text-flow discontinuity, incorrect text hit testing, paragraph formatting, baseline shift, preflight cache reuse, PDF page count, PDF font selection, ignored image transforms, and an invalid PDF/X-1a claim.
- These are Windows CPU/code-path checks. I did not perform interactive GUI validation, Linux/macOS runtime checks, GPU rendering comparisons, or certification through a PDF/X validator or production RIP. Source-confirmed findings below explicitly distinguish themselves from executed reproductions.
- The review sampled important paths across the workspace; it is not proof that every module or behavior is defect-free.

**Bugs to address first**

P1 means urgent correctness, data-safety, or production-output work. P2 means an important functional defect. “Reproduced” means an isolated harness exercised the implementation; “source-confirmed” means the relevant code path establishes the issue without a native GUI run.

1. **[P1] Closing the application can discard unsaved work and remove its recovery copy.** Source-confirmed. The application implements no native close-request interception; its only unsaved-change dialog belongs to document tabs. `on_exit` unconditionally discards recovery. Closing the OS window therefore bypasses the tab safeguard. Add a window-close state machine covering every dirty document, cancel the close while decisions/saves are pending, and delete only recovery files whose work was saved or explicitly discarded. Locations: [crates/tessera_ui/src/lib.rs:68](C:/Users/hailmary/Downloads/tessera-publisher/crates/tessera_ui/src/lib.rs:68), [crates/tessera_ui/src/view/document_tabs.rs:163](C:/Users/hailmary/Downloads/tessera-publisher/crates/tessera_ui/src/view/document_tabs.rs:163).

2. **[P1] Duplicating a group shares its original children; deleting the duplicate deletes the original artwork.** Reproduced. `duplicate_one` clones the outer frame and gives text its own story, but leaves `Group(Vec<FrameId>)` unchanged. The reproduction produced four frames instead of six; deleting the duplicate left zero original drawable children. Implement recursive subtree cloning with old-to-new ID mapping, and use it for duplicate and step-and-repeat. Locations: [crates/tessera_ui/src/command.rs:1725](C:/Users/hailmary/Downloads/tessera-publisher/crates/tessera_ui/src/command.rs:1725), [crates/tessera_document/src/document.rs:1838](C:/Users/hailmary/Downloads/tessera-publisher/crates/tessera_document/src/document.rs:1838).

3. **[P1] The clipboard does not carry the object graph and its resources.** Reproduced. Cut/paste of a two-child group restored zero drawable children. Copying a placed graphic into a second document created no destination link. Clipboard entries contain only a frame and optional story; child IDs, link IDs and style IDs remain references into the source document. They can be missing or collide with unrelated destination resources. Serialize a selection subtree plus its required stories, links, styles and swatches, then remap all references during paste. Locations: [crates/tessera_ui/src/app.rs:20](C:/Users/hailmary/Downloads/tessera-publisher/crates/tessera_ui/src/app.rs:20), [crates/tessera_ui/src/command.rs:1132](C:/Users/hailmary/Downloads/tessera-publisher/crates/tessera_ui/src/command.rs:1132), [crates/tessera_ui/src/command.rs:1708](C:/Users/hailmary/Downloads/tessera-publisher/crates/tessera_ui/src/command.rs:1708).

4. **[P1] PDF export always creates one page.** Reproduced with two input pages and an exported `/Count 1`. The writer chooses `resolved.pages.first()`, allocates one page/content pair and uses a single page tree child. It passes the complete item list into that one page's content builder. Later pages do not become PDF pages and their content can fall outside the exported page. Write each page in reading order with its own geometry, content and appropriate clipping/page membership. Locations: [crates/tessera_pdf/src/writer.rs:153](C:/Users/hailmary/Downloads/tessera-publisher/crates/tessera_pdf/src/writer.rs:153), [crates/tessera_pdf/src/writer.rs:215](C:/Users/hailmary/Downloads/tessera-publisher/crates/tessera_pdf/src/writer.rs:215).

5. **[P1] Independent text frames select the wrong embedded PDF font.** Reproduced with Arial and Times New Roman frames: both selected `/F0 12 Tf`. A shaped frame's font index is local to that frame, while the embedded font collection spans the whole export. `font_for` simply clamps the local index into the global collection. This can change typefaces, map glyph IDs to unrelated glyphs, or omit glyphs absent from the chosen subset. Map each shaped font identity to its actual embedded resource and subset remapping. Locations: [crates/tessera_pdf/src/writer.rs:1450](C:/Users/hailmary/Downloads/tessera-publisher/crates/tessera_pdf/src/writer.rs:1450), [crates/tessera_pdf/src/writer.rs:1489](C:/Users/hailmary/Downloads/tessera-publisher/crates/tessera_pdf/src/writer.rs:1489).

6. **[P1] PDF output ignores picture fitting and content movement.** Reproduced: translating image content by (-40, -20) points produced byte-identical PDF bytes. The graphic branch uses frame width/height and discards `inner` and `natural`; it therefore stretches the image to the frame rather than honoring the screen's fitting/crop transform. Apply the same content transform and frame clipping used by rendering, and preserve graphic-frame strokes. Location: [crates/tessera_pdf/src/writer.rs:1070](C:/Users/hailmary/Downloads/tessera-publisher/crates/tessera_pdf/src/writer.rs:1070).

7. **[P1] Threaded text can disappear when a preceding frame uses a baseline grid or wrap.** Reproduced with a 90-point-wide first frame, height 70, and a 30-point baseline grid. Its visible lines ended at byte 28, but the next frame began at byte 56: “seven eight nine ten eleven ” disappeared. The start-offset calculation uses ordinary shaping/flow, while final drawing uses wrapping and grid-aware flow. Compose a story once through its chain and carry the actual consumed range forward. 8. **[P1] Text hit testing and caret placement use different layout from the displayed frames.** Reproduced at the shaper call used by the UI: clicking the beginning of the second frame returned story offset 0 although its displayed first line started at 56. The UI measures the whole story at the full frame width, without using the resolved thread range, columns, insets or grid/wrap positions. Editing may therefore modify text elsewhere in the story. Derive caret, selection, mouse hit testing and IME geometry from the same composed frame layout used to draw. 9. **[P1] Recovery is still a single-document subsystem in a multi-document application.** Source-confirmed. There is one global `recovery.tessera`, one saved revision, and autosave only visits the active document. Equal revision numbers in different documents are treated as the same work. Saving any document deletes the shared recovery file, potentially removing another dirty document's backup. Use a session manifest and a separate recovery file/revision per document; save and close should retire only that document's recovery. 10. **[P1] PDF/X-1a can be claimed for output containing transparency and RGB.** Reproduced with a transparent PNG and an sRGB output profile: export succeeded and wrote `PDF/X-1a:2003`, `/SMask` and `/DeviceRGB`. **What is already present**

The project contains typed document IDs, persistent stories and style cascades, serialization/migrations, undo history, affine geometry, paths and groups, master pages, spreads and layers, text columns/insets/threading, English hyphenation, drop caps, bidirectional shaping, image links and fitting, swatches, ICC transforms, preflight, PDF resources, docking, preferences, and keyboard mappings. These should not be described as wholly missing. Their presence is different from end-to-end reliability.

The division into document, geometry, text, layout, render, preflight, PDF and UI crates is worth retaining. The bugs identified here do not establish a need to replace Rust, egui, Vello, Parley or kurbo.

**Missing or incomplete publishing capabilities**

This assessment comes from the current models, command catalogue, import/export paths and shaping code, rather than the older parity document's checkboxes. “Absent” means no implementation was found in the audited paths and repository-wide capability searches.

| Priority | Capability | Current gap and practical consequence |
|---|---|---|
| Next after correctness | Editorial text operations | No find/change workflow, regex/style-aware replacement or spellchecking found. Cleaning and revising supplied copy remains manual. |
| Next after correctness | Text import | Place accepts PNG/JPEG; no DOCX/RTF text import with style mapping, tables or notes found. Authors' manuscripts cannot enter a normal publishing workflow with structure preserved. |
| Next after correctness | Structured tables | No table/cell model, table/cell styles, repeated headers or table pagination found. Essential for reports, catalogues and manuals. |
| Next after correctness | Paragraph composition | No tab stops/leaders, automatic bullet/numbered-list model, keep-with-next, widow/orphan controls or controlled H&J ranges found. Manual kerning and optical kerning are also absent. |
| Next after correctness | Languages and character controls | Hyphenation is explicitly hardcoded to English. CharacterFormat has no language or general OpenType/variable-axis controls, and no underline/strikethrough model. Small caps support does exist. |
| Next after correctness | Artwork interchange | No PDF/SVG/TIFF/PSD placement pipeline found; PNG/JPEG-only is restrictive for print artwork. Prioritize PDF/SVG and TIFF according to target users. |
| Strategic | Existing InDesign documents | No IDML import/export found. Define and test a supported IDML subset, with a conversion-loss report, so adoption does not require rebuilding every existing layout. |
| Strategic for books | Long-document structure | No footnotes/endnotes, generated TOC/index, cross-references, book/chapter management or running-header variables found. These need document semantics and pagination support. |
| Strategic for production | Print verification and control | Export needs the correctness fixes above plus an independent PDF/X validation corpus, separation/output inspection, overprint/knockout controls, and real RIP checks. Existing spot colors and ICC conversion do not complete these workflows. |
| Strategic for automation | Data-driven publishing | No data merge, supported scripting/plugin API or batch publishing CLI found. Repetitive catalogue and variable-data work has no automation surface. |
| Strategic for digital/accessibility work | Structured digital export | No EPUB export, tagged-PDF structure/reading order, alt-text workflow or PDF Unicode mapping found. Search/copy/extraction and assistive-technology behavior need explicit tests. |
| Required for the OS goal | Desktop integration and accessibility | Complete native file-open handling, keyboard-accessible canvas objects/text, and installed-app checks for Linux Wayland/X11, macOS and Windows, including IME, scaling, dialogs and font fallback. Existing cross-platform CI is build evidence, not interactive proof. |

For comparison, Adobe documents IDML interchange, Word import and multi-page PDF placement in its [supported-format reference](https://helpx.adobe.com/indesign/desktop/get-started/system-and-product-info/supported-file-formats.html); editable tables in its [table workflow](https://helpx.adobe.com/ae_en/indesign/using/creating-tables.html); automation through [data merge](https://helpx.adobe.com/indesign/desktop/automation-and-scripting/merge-data/merge-data.html); and semantic digital output through [EPUB accessibility](https://helpx.adobe.com/indesign/desktop/save-export-and-publish/export-to-epub/epub-accessibility-features.html). These are workflow references, not a recommendation to copy every InDesign feature.

**Recommended development order**

1. **Protect existing work.** Fix application close, per-document recovery, group ownership, clipboard resource remapping and portable packaging. Acceptance: duplicate/cut/paste mixed nested groups between two documents, save and reopen, then simulate a crash with both dirty.
2. **Unify composition.** Make one composed story/frame result supply drawing, hit testing, selection, IME geometry, thread offsets and overset preflight. Acceptance: text flows continuously across differently sized columns with wrap, grid and insets; selecting a displayed word edits that exact word.
3. **Make export match the document.** Correct per-page export, font resource mapping, image transforms/clipping and strokes; validate standard claims. Acceptance: a mixed-font, multi-page specimen has all pages and the same geometry/content in canvas and independently rendered PDF.
4. **Deliver a narrow professional workflow.** Add manuscript import, find/change, tables and paragraph controls before expanding decorative drawing tools. Choose a representative brochure/report job and test the complete author-to-print process.
5. **Expand interchange and scale.** Add IDML, long-document semantics, automation and digital accessibility as separate milestones with explicit supported scope. Measure large-document editing, composition, memory and export, including undo history.
6. **Verify each installed platform.** Test native launching, recovery, IME, keyboard navigation, fractional scaling and color/font behavior on real installations.

The strongest missing tests are combinations, not additional isolated getters: group duplication followed by deletion; clipboard across documents; two documents at equal revision; a threaded story with wrap/grid; multiple fonts in independent frames; image fitting through PDF export; and multiple pages through a parser or renderer.
